I'm currently working on defining the direction of my M.Sc. thesis in Software Engineering.

My main area of interest is the use of Large Language Models in software development, particularly in tasks related to code review and software quality. At this stage, I'm still exploring the literature and trying to understand where the most interesting and practical research gaps are.

One direction I'm considering is LLM-assisted code review: how language models can help developers identify issues, reason about code changes, and improve the review process.

## Questions I'm currently exploring

- How are LLMs currently being used in code review?
- What types of issues can they identify reliably?
- How do existing approaches evaluate the quality of LLM-generated reviews?
- What are the main limitations of current methods?
- How can we evaluate usefulness from a developer's perspective, rather than relying only on accuracy-based metrics?

## What I'm doing next

My next step is to read and organize recent papers related to LLM-assisted code review, automated code review, and AI for Software Engineering.

For each paper, I want to keep track of the problem it addresses, the proposed method, the evaluation setup, the main findings, and any limitations or open questions that could be relevant to my thesis.

The goal for now is not to lock in a thesis topic too early, but to gradually narrow the scope based on what I find in the literature.

I'll use these logs to document that process as it develops.
